# Структура документа

Человек не читает справку подряд. Он ищет глазами заголовок, который похож на его вопрос, и первый шаг. Структура должна помогать именно этому.

## Заголовки

**Обязательно.**

- У страницы один заголовок первого уровня. Он совпадает с пунктом навигации.
- Уровни не пропускаем: после `##` идёт `###`, а не `####`.
- Глубже третьего уровня не уходим. Если хочется четвёртый, страницу пора делить.
- В конце заголовка точку не ставим.

**Рекомендуется.** Заголовок инструкции формулируем как задачу пользователя, через инфинитив или вопрос «Как…».

<!-- style-check: off -->

| Плохо | Хорошо |
|---|---|
| Функционал импорта | Как загрузить выписку из банка |
| Категории | Создать свою категорию расходов |
| Ошибки синхронизации | Что делать, если баланс не совпадает с банком |

<!-- style-check: on -->

## Первый абзац

<!-- style-check: off -->

**Обязательно.** Первые два предложения страницы говорят, что здесь можно сделать и кому это нужно. Без истории вопроса и без «В данном разделе рассматривается…».

<!-- style-check: on -->

## Списки

**Обязательно.**

- Нумерованный список — для шагов, которые выполняют по порядку. Маркированный — для всего остального.
- Один шаг — одно действие. «Откройте „Портфель“ и нажмите **+**» допустимо, если действия происходят на одном экране.
- В списке не меньше двух пунктов.
- Пункты оформляем одинаково: если один начинается с глагола, остальные тоже.

**Пунктуация в списках.** Если пункты — законченные предложения, каждый начинаем с прописной и заканчиваем точкой. Если пункты продолжают фразу перед списком, пишем со строчной, разделяем точкой с запятой, в конце последнего ставим точку.

## Таблицы

**Рекомендуется.** Таблица нужна, когда сравниваем объекты по одинаковым признакам: тарифы, поля API, форматы. Если в таблице две колонки и пять строк текста, лучше сделать список.

- У каждой колонки есть заголовок.
- Числа выравниваем по правому краю (`---:`).
- Пустых ячеек не оставляем. Нет значения — пишем «нет» или «—».

## Выделения

**Обязательно.**

- **Полужирным** выделяем названия кнопок и элементов, на которые надо нажать, если они без кавычек: «нажмите **+**». Больше ничего.
- *Курсив* не используем: на экране телефона он плохо читается.
- `Моноширинный шрифт` — для кода, команд, путей, имён полей API и значений, которые вводят буквально.
- Подчёркивание не используем, его путают со ссылкой.

## Врезки

**Рекомендуется.** В MkDocs есть врезки (admonitions). Используем три типа и не больше одной врезки на экран:

- `note` — полезная деталь, без которой можно обойтись;
- `warning` — действие нельзя отменить или оно влияет на деньги и данные;
- `tip` — способ сделать то же быстрее.

```markdown
!!! warning "Удаление счёта нельзя отменить"
    Вместе со счётом удалятся все его операции.
```

## Ссылки

**Обязательно.**

- Текст ссылки описывает, куда она ведёт: `[как считается доходность](returns.md)`, а не `подробнее [здесь](returns.md)`.
- На другие страницы руководства ссылаемся относительным путём к `.md` файлу, чтобы MkDocs проверял ссылки при сборке.

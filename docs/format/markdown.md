# Правила Markdown

Документация «Сальдо» хранится в Markdown рядом с кодом и собирается MkDocs. Эти правила проверяет `markdownlint-cli2` с конфигурацией из [`.markdownlint-cli2.yaml`](https://github.com/lk2322/style-guide-project/blob/main/.markdownlint-cli2.yaml).

## Файлы

**Обязательно.**

- Имя файла — латиница в нижнем регистре через дефис: `add-bond.md`, `api-operations.md`.
- Кодировка UTF-8, перевод строки LF, в конце файла одна пустая строка.
- Изображения кладём в `docs/assets/<раздел>/`. Имя картинки повторяет имя страницы: `add-bond-step-2.png`.

## Синтаксис

**Обязательно.**

| Элемент | Как пишем | Правило линтера |
|---|---|---|
| Заголовки | Через `#`, не через подчёркивание `===` | MD003 |
| Маркированный список | Дефис `-` | MD004 |
| Вложенный список | Отступ 4 пробела | MD007 |
| Нумерованный список | `1.`, `2.`, `3.` по порядку | MD029 |
| Блок кода | Три обратных апострофа и язык | MD040, MD046 |
| Пустые строки | Вокруг заголовков, списков, блоков кода | MD022, MD031, MD032 |

Отступ вложенных списков — именно 4 пробела. Python-Markdown, на котором работает MkDocs, не видит вложенность при двух.

## Блоки кода

**Обязательно.** Всегда указываем язык: `bash`, `kotlin`, `json`, `http`, `yaml`. Без языка нет подсветки, а линтер выдаст ошибку.

Команды для терминала пишем без приглашения `$`, чтобы их можно было скопировать целиком:

```bash
pip install -r requirements.txt
mkdocs serve
```

Вывод команды, если он нужен, кладём в отдельный блок с языком `text`.

## HTML внутри Markdown

**Рекомендуется.** Не используем. Исключение — `<kbd>` для клавиш, но лучше синтаксис `++ctrl+c++` из расширения `pymdownx.keys`.

## Длина строки

Строки не переносим вручную: один абзац — одна строка. Так диф в пул-реквесте показывает изменения точнее, а редакторы сами переносят текст по ширине окна. Правило MD013 отключено.

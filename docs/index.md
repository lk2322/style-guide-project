# О руководстве

«Сальдо» — мобильное приложение для учёта доходов, расходов и инвестиций. В нём пользователь ведёт счета, записывает операции, раскладывает траты по категориям и следит за брокерским портфелем: акциями, облигациями, фондами.

Это руководство описывает, как мы пишем документацию проекта. Его задача простая: чтобы справка, README и описание API звучали как один текст, а не как пять разных авторов.

## Для кого

Руководство нужно всем, кто пишет или правит документацию «Сальдо»:

- разработчикам мобильного клиента и бэкенда, которые пишут README, описания API и заметки о выпуске;
- тем, кто готовит пользовательскую справку и тексты для раздела «Помощь»;
- ревьюерам, которые проверяют пул-реквесты с документацией.

## Какие документы покрывает

| Документ | Читатель | Где лежит |
|---|---|---|
| Пользовательская справка | Пользователь приложения | Раздел «Помощь» в приложении и сайт справки |
| README и руководства разработчика | Участник команды | Репозитории клиента и бэкенда |
| Описание REST API | Разработчик клиента или интеграции | `docs/api` в репозитории бэкенда |
| Заметки о выпуске | Пользователь и команда | Страница в магазине приложений, `CHANGELOG.md` |

## Как пользоваться

1. Перед тем как писать новый документ, возьмите шаблон из раздела «Шаблоны».
2. Сомневаетесь в слове — проверьте [глоссарий](glossary.md).
3. Перед пул-реквестом запустите линтер: `make lint`. Он ловит большую часть нарушений автоматически.
4. Не нашли ответ — откройте issue с меткой `style-guide`. Новое правило добавляем, когда один и тот же вопрос возникает второй раз.

## Как устроены правила

У каждого правила есть уровень:

- **Обязательно** — нарушение блокирует пул-реквест. Линтер или ревьюер вернут текст на доработку.
- **Рекомендуется** — отступить можно, если есть причина. Причину пишут в описании пул-реквеста.

Рядом с правилом обычно стоит пример «Плохо / Хорошо». Пример важнее формулировки: если они расходятся, ориентируйтесь на пример и откройте issue.

!!! note "Чего здесь нет"
    Руководство не описывает визуальный дизайн приложения (цвета, иконки, сетку) и стиль кода. Для этого есть дизайн-система в Figma и конфигурации линтеров в репозиториях.

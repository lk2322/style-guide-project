# Документация разработчика

Правила для README, описаний API и заметок о выпуске. Общие правила языка и оформления действуют и здесь, но читатель другой: он знает предмет и хочет быстро найти команду или поле.

## README

**Обязательно.** README любого репозитория «Сальдо» содержит разделы в таком порядке:

1. Что это — один абзац о назначении репозитория.
2. Быстрый старт — команды, после которых проект запускается локально.
3. Конфигурация — переменные окружения в таблице: имя, назначение, значение по умолчанию.
4. Тесты — как запустить.
5. Как внести изменения — ссылка на `CONTRIBUTING.md`.

Команды в быстром старте проверяем на чистой машине перед каждым выпуском.

## Описание API

**Обязательно.** Каждый метод описываем по [шаблону](doc-templates/api-method.md):

- метод и путь в заголовке: `POST /operations`;
- одно предложение о том, что метод делает;
- таблица параметров: имя, тип, обязательность, описание;
- пример запроса и ответа в формате JSON;
- коды ответа с объяснением, когда каждый возникает.

Суммы в API передаются в минорных единицах (копейках) целым числом. В описании полей это пишем явно: «`amount` — сумма в копейках, целое число».

Имена полей, значения перечислений и пути пишем `моноширинным` шрифтом и не переводим.

## Комментарии в коде

**Рекомендуется.** Комментарии в коде пишем на русском, KDoc и docstring публичных методов — тоже на русском. Комментарий объясняет, почему так сделано, а не пересказывает код.

## Сообщения коммитов

**Обязательно.** Используем [Conventional Commits](https://www.conventionalcommits.org/ru/v1.0.0/). Тип на английском, описание на русском, в повелительном наклонении, со строчной буквы, без точки:

```text
feat(portfolio): добавить расчёт купонного дохода
fix(api): вернуть 404 вместо 500 для удалённого счёта
docs(style): описать формат отрицательных сумм
```

Подробности — в [`CONTRIBUTING.md`](https://github.com/lk2322/style-guide-project/blob/main/CONTRIBUTING.md).

## Заметки о выпуске

**Обязательно.** Пишем по [шаблону](doc-templates/release-notes.md) для пользователя, а не для команды. Не «рефакторинг модуля синхронизации», а «баланс обновляется быстрее после загрузки выписки».
